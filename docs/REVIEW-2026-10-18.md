## Blockers — found and fixed

### 1 · The answer-window timeout never reached the players

`main.py`, `cancel_timer()` / `do_reveal()` / `run_round()`.

When a player sat out the 90-second answer window, the timer task fired `do_reveal()`,
which began by calling `cancel_timer()` — on **itself**. The cancellation landed on the
next `await`, inside `push_state()`, so the reveal was applied to the room but never sent
to a single client. The old `except asyncio.CancelledError: pass` around the timer body
hid the failure completely.

Consequence: everyone sat on "answering" with no way forward. The room was in
`REVEALING`, so a late answer was refused, and the host's **Next song** button only
renders in the revealing phase they could not see. The table was wedged until somebody
reconnected, because a rejoin pushes state. The timer exists to stop an absent player
stalling the table; it was the stall.

Fixed: `cancel_timer()` pops the task but never cancels the current one. Covered by
`test_an_absent_player_cannot_stall_the_table`, which fails on the old code.

### 2 · Next.js 15.1.11 carried unauthenticated RCE, SSRF and cache-poisoning advisories

`client/package.json`. `npm audit --omit=dev` listed 31 advisories against the pinned
Next.js, among them unauthenticated remote code execution in image optimisation and on
Windows hosts, SSRF through middleware redirects, and cache poisoning of server
components. A previous PR had patched the React Server Components CVE but left the
framework itself behind.

Fixed: Next.js **15.5.28**, the maintained 15.x backport line, with a `postcss` override
to the patched release that 15.5 still pins below. Production audit is now **0**. Next 16
is a major upgrade with breaking changes and is listed under follow-ups.

## High — found and fixed

### 3 · Half of the database was write-only

`db.py` had `players`, `rooms` and `room_players` tables, and `main.py` wrote to them on
every join and reveal. Nothing ever read them back: `room_snapshot()` and `get_player()`
had no callers, and `on_join` rebinds from the in-memory `rooms` dict. The docs said
SQLite held "enough room state to seat a returning player back where they were" and
DEPLOY.md suggested a volume would preserve games across restarts. Neither was true. A
restart lost every game regardless; the tables were a false promise and ~110 lines of
code.

Removed, rather than finished: restoring a game after a restart would also need the
current card and timers rebuilt, which is a feature to design, not a flag to flip.
`db.py` now holds the deck and nothing else, and ARCHITECTURE.md and DEPLOY.md say so.
If restore is ever wanted, git history has the schema.

### 4 · The deck token gate had no client

`DECK_TOKEN` made `POST` and `DELETE /deck` require `?token=`, but the `/deck` page had
no way to send one. Setting the variable — the documented way to protect the deck once
the URL leaves the group — made the editor unusable. Meanwhile anyone with the URL of an
unprotected server could delete every card with one tap, no confirmation.

Fixed: the page reads `?token=` from its own URL once, remembers it, and sends it on
every edit; a 403 is explained in words. Remove now asks first. The gate itself uses
`secrets.compare_digest`. Covered by `test_deck_token_gates_writes_but_not_reads`.

### 5 · Abandoned rooms lived forever on a quiet server

`drop_empty_rooms()` only ran on a disconnect. A room whose players all left started its
15-minute grace period, but the period could only *expire* on a later disconnect — from
anyone, in any room. On a server with one group playing, that is "never". There were
also no unit tests for the grace logic that the September review called its worst bug.

Fixed: a reaper task runs every 60 seconds from the app's lifespan, and four tests cover
the grace period, the reset on reconnect, and that a room with anyone connected is never
reaped.

### 6 · Loss of deck edits was only detected on Render

`storage_is_ephemeral()` keyed on `RENDER=true`. The repository ships a `fly.toml` and
DEPLOY.md recommends Fly, where the same loss happens on every deploy without a volume.
On Fly the page would have said nothing. Fixed: `FLY_APP_NAME` is detected too, with the
same `DECK_STORAGE` override, and tested.

### 8 · Modules that had drifted off their stated job

- The deck-file logic (export, diff, baseline load) had been added to `db.py`, whose
  docstring says "SQLite persistence". It now lives in **`deck.py`**, with `card_id`, the
  year bounds, `is_playable()` and `card_from_row()`, which replaces an eleven-line
  `Card(...)` constructor in `main.py`.
- `main.py` talked to Deezer directly, with an inline `import httpx`. The search is now
  `sources.deezer_search()`, shared with `deezer_probe()`, so one module owns Deezer and
  the "no answer" vs "empty answer" distinction is made in one place.
- The year bounds existed three times: `1900–2030` in `main.py`, `1900–2026` hardcoded
  in the CLI, and `1900–2030` in the client. Now `EARLIEST_YEAR` and `LATEST_YEAR` (this
  year) in `deck.py`, mirrored by the client with `new Date().getFullYear()`.
- The client hardcoded 70/30 while ignoring the `maxRoundScore` the server sent. The
  server now sends `artistPoints` and `yearPoints`, the rules own the numbers, and the
  room page renders them.

### 9 · API and validation

- `deezer_track_id` travelled as a query parameter on a JSON `POST`. It is in the body.
- `NewCard` accepted whitespace-only names (`min_length=1` before stripping). Pydantic
  `StringConstraints(strip_whitespace=True)` now strips first; a blank name is a 422.
- Player names had no cap on either side; they are shown on every screen. 40 characters.
- `CORS_ORIGINS` with spaces after the commas produced origins that never matched.
- `FastAPI(lifespan=…)` replaces poking `api.router.lifespan_context`.

### 10 · Tests

- Every test file patched `sys.path`. `pytest.ini` now sets `pythonpath = .`.
- Tests moved to match their modules: catalogue matching and `normalize` live in
  `test_matching.py`; `test_sources.py` now drives `deezer_search` and `deezer_probe`
  against a fake Deezer through `httpx.MockTransport`, covering the field-scoped query,
  the refusal of a wrong artist, and no-answer vs empty-answer. The probe's rule — never
  attach a wrong track — had no test before.
- `test_deck.py` replaces the untracked `test_deck_export.py` and adds checks that the
  committed `deck.json` is canonical, playable and within the year bounds, so a hand
  edit fails CI rather than showing up as spurious diffs on the next download.
- The integration suite's six copies of create/join/start setup became one helper, and
  it gained the timeout test, the token gate, validation, and `/deck/search` through the
  fake. 136 → **158** tests.

### 11 · Tooling that was missing or broken

- `server/ruff.toml`: lint (not format — the compact field tuples and serialised dicts

- `client`: ESLint installed and configured (`next/core-web-vitals`), plus a

- `.github/workflows/ci.yml`: server lint + tests + a seed of the committed deck, client

- `.claude/launch.json` gained the server, so both halves start from the app.
